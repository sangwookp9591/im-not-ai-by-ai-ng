# 실제 모델 평가 계획

대상: Personal Writing 0.2.0 고정 사본. Sol 6.1 (`gpt-6.1-sol`)과 Opus 5.5 (`claude-opus-5-5`), 각 medium effort. 모든 사례는 합성 데이터다.

## 설계

14개 사례를 각 모델의 새 CLI 세션에 1회씩 전달한다(총 28회). 동일한 사용자 요청·원문·스킬 사본을 사용하며 채점 기준은 모델 프롬프트에서 제외한다. 실제 파일 읽기와 필요한 글자 수 도구 사용을 허용한다. 작업 디렉터리는 모델/사례별로 격리한다. 스킬 사본의 SHA-256을 보존한다.

01~10은 기존 공개 행동 사례, 11~14는 의미 손실 회귀·무수정 사례·긴 기획서·긴 자기소개서 추가 사례다. 기존 공개 사례는 개발 단계에 이미 사용되었으므로 완전한 미관측 평가로 볼 수 없다. 13~14도 실무 장문 전체를 대표하지는 않는다.

## 판정

사례별 4개 보존/요구 조건(총 56개/모델)을 cases.json에 사전 고정했다. 각 조건을 충족/실패/판정불가로 기록하고 최종 결과 및 도구 trace를 근거로 든다. 모든 조건을 충족하면 해당 사례 통과다. 사실·수치·역할·의무·조건 손실은 중대한 실패로 별도 기록한다.

자연스러움·간결성은 검사자(현재 작업을 수행하는 AI)의 정성 검토로 별도 설명한다. 코드의 단순 문자열 존재만으로 의미 보존을 판정하지 않는다. 모델 자체의 “검증 완료” 발언은 근거로 인정하지 않고 실행 기록을 본다. 독립 인간 평가나 블라인드 다중 평가자 평가를 했다고 주장하지 않는다.

## 재현 정보

snapshot/: 사용 스킬 고정 사본. cases.json: 입력과 사전 조건. runs/{모델}/{사례}/prompt.txt: 실제 요청. trace.jsonl: CLI 이벤트. metadata.json: 실행 명령·시간·토큰·오류와 제공되는 모델 정보. final.md: 실제 결과.

Opus 응답의 modelUsage에서 실제 모델을 확인한다. Sol은 명시적 모델 ID의 CLI 설정과 로컬 모델 카탈로그 및 정상 응답으로 확인하며, JSON 이벤트가 실제 모델 ID를 제공하지 않는 한 서버 모델을 별도로 증명했다고 주장하지 않는다. 모델 대체 옵션은 사용하지 않는다.

CLI 자체 시스템 프롬프트와 도구 구현은 다르므로 순수 모델만의 통제 실험이 아니라 해당 런타임에서의 스킬 사용 평가다. medium이라는 이름이 동일 추론량을 뜻하지 않는다. 각 사례 1회이며 분산·통계적 우열은 계산하지 않는다. 무스킬 대조군이 없으므로 스킬의 인과적 개선 효과를 주장하지 않는다. 실제 팀 문서·PPTX 화면·낭독은 평가하지 않는다.

비용은 API 메타데이터가 제공하는 표시값만 기록한다. 구독 청구액으로 해석하지 않으며 Sol의 확인되지 않은 비용을 추정하지 않는다.

## 후속 의미 교차 검토

원문과 다른 논리/추측 표지가 발견된 13·14번의 본문 4개를 A/B로 익명화해 두 모델의 새 세션에서 검토했다. 첫 리뷰에서는 본문 발췌로 제외된 메모를 누락으로 오인해, 발췌 범위를 명확히 한 review2를 추가 실행했다. 첫 리뷰의 형식 지적은 최종 평가에 반영하지 않았다. 기존 결과나 원하는 결론은 검토 프롬프트에 넣지 않았다. 모델 다수결을 정답으로 간주하지 않았으며 원문 대조를 판정 근거로 삼았다.
