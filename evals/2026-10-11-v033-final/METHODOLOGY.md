# 실행·판정 방법

- 생성 모델: `gpt-6.1-sol`, `claude-opus-5-5`, 양쪽 medium. `run_eval.py`가 실제 CLI를 실행한다. 모델 대체 없음.
- 스킬 경로를 명시하고 공통/타입 규칙을 직접 읽도록 요청한다. 32개 고유 입력 + 7개 반복 = 39회/모델. 스킬 없는 대조군이나 자동 스킬 탐색 시험은 아니다.
- 사례마다 새 작업 폴더·일회 세션을 사용한다. 공통 스냅샷과 원문·요청은 같지만 두 런타임의 시스템 지침/캐시/도구 환경까지 동일하지는 않다. 같은 이름의 medium도 동일한 연산량을 뜻하지 않는다.
- `cases.json`의 checks/repeat_of는 평가자가 보는 정보다. 생성 프롬프트에는 스킬 경로, 요청, 원문만 제공한다. 중간 수정의 실패 사례도 지우지 않는다. 최종 후보 선택에 쓰인 사례는 홀드아웃 일반화 성능으로 보고하지 않는다.
- 원문·결과를 작업 에이전트가 직접 대조한다. 의미와 사용자 제약, 필요한 교정 수행, 형식 순응은 별도로 판정한다. 본문에 없던 수치/역할/인과/확신이 생기는지, 미확정 상태와 의무·예외가 남는지 확인한다.
- 글자 수는 최종 응답의 본문을 다시 세고 모델 보고와 대조한다. `text_stats.py` 실행만으로 수치가 맞는다고 판정하지 않는다. 의미 판정은 길이 도구나 단어 존재 검사로 대체하지 않는다.
- 별도 새 세션의 두 모델에 원문과 익명화한 결과를 주어 검토한다. 작업 에이전트의 채택 결론은 주입하지 않는다. 모델 간 합의도 정답 보장은 아니며, 이견은 원문 근거로 판단해 남긴다.
- Opus 응답의 modelUsage에서 실제 반환 모델 식별자를 확인한다. Sol은 CLI의 명시 모델 옵션과 정상 종료를 기록하지만 반환 이벤트에 서버 모델 ID가 없으므로 서버 측 독립 확인이라고 주장하지 않는다.
- 실행 시간은 로컬 벽시계, 응답 길이는 최종 Markdown 전체의 Python len이다. 원래 14개만 비교해 사례 추가로 인한 평균 왜곡을 줄인다. 속도/길이를 품질 점수로 환산하지 않는다.
- Opus의 costUSD는 CLI가 보고한 API list-price 환산값이며 구독 청구액이 아니다. Sol은 같은 비용 지표가 없어 비용 우열을 비교하지 않는다.

## 기록과 재실행

`runs/<provider>/<id>/`에 prompt, final, metadata 및 모델이 작성한 본문 파일이 있다. 원시 trace/stderr는 로컬에만 남기며 저장소에 게시하지 않는다. `execution-summary.json`은 원시 로그에서 공통 계약 내용 확인과 길이 도구 실행 여부를 추출한 기록이다. 원시 로그 없이 재집계하면 해당 필드는 null이 되며, 공개 저장소만으로 과거 도구 실행 전체를 재감사할 수는 없다.

`python3 run_eval.py --workers 4`로 같은 사례를 실행한다. 기존 실행을 덮어쓰지 않으므로 새 평가 폴더에 cases.json/run_eval.py/snapshot/snapshot-sha256.json을 복사해서 실행해야 한다. 인증된 두 CLI가 필요하다. 결과 집계는 저장소 루트에서 `python3 evals/collect_evidence.py evals/<평가폴더>`로 실행한다.

해시는 평가용 소스 14개만 검사한다. Python이 만든 __pycache__/pyc는 소스도 배포 대상도 아니므로 제외한다. 각 실행이 규칙 파일을 수정하지 않았는지 해시로 확인한다. 본문/메모 경계의 의미 판정과 글자 수 대조는 assessment 및 length-audit 기록을 함께 본다.

## 일반화 한계

한국어 합성 사례이며 사람이 만든 실제 문서의 맹검 평가가 아니다. 장문 실무 문서, 직무별 자기소개서, PPTX 렌더링, 리허설 시간, 배포 후 자동 호출 품질은 이번 시험으로 보장하지 않는다. 이 패키지는 검토·윤문 규칙이며 문서 디자인 도구나 확정적인 AI 문체 판별기가 아니다.
