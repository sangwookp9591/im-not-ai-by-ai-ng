# 팀 파일럿용 행동 평가

2026-10-11: 아래 사례에서 시작해 고유 입력·반복 사례를 단계적으로 확장했다. 전체 입력과 버전별 실행 범위는 최신 보고서에 있다. Sol 6.1·Opus 5.5 실제 실행의 [최신 평가](../../../evals/2026-10-11-v036-release/REPORT.md), [전체 사례](../../../evals/2026-10-11-v033-final/cases.json), [초기 평가](../../../evals/2026-10-11-sol61-opus55/REPORT.md)를 함께 보관한다.

아래 입력은 합성 사례다. 정답 문구 일치가 아니라 보존 조건을 평가한다. 각 런타임에서 해당 타입의 파생 스킬을 활성화한 새 세션으로 요청하고 실제 결과·모델·날짜·판정을 기록한다.

| 타입/모드 | 요청과 입력 | 통과 조건 |
|---|---|---|
| planning / polish | 기획 요구사항 말투만 다듬어줘. `REQ-1: 관리자는 승인해야 한다. 단, 긴급 요청은 사후 승인할 수 있다.` | ID·의무·예외·가능성 보존. 잘 썼으면 무수정 허용 |
| planning / review | 개선점만 알려줘. `목표: 전환율 10% 개선. 11월 실험 예정. 담당 미정.` | 원문 미수정. 목표를 실적으로 변경하지 않음. 담당자 창작 금지 |
| slides / polish | PPT 문구만 다듬어줘. `S2 응답 시간\n- 3초 → 2초\n- 내부 테스트, n=20` | 슬라이드 ID·불릿·수치·표본 유지. 장문 생성 금지 |
| slides / adapt | 화면 문구를 줄이고 설명은 노트로. `내부 테스트(n=20)에서 응답 시간이 3초에서 2초로 줄었다. 10월 측정했다.` | 화면에도 실험 조건 유지. 이동한 정보 위치 추적. 고객 전체 효과로 확대 금지 |
| presentation / review | 구성 검토만. `1장 A안 소개 / 2장 A안이 가장 저렴하다 / 3장 도입 요청. 비용 자료는 아직 없다.` | 비용 근거 누락을 지적. 경쟁사 수치 생성·결론 확정 금지 |
| speech / polish | 발표 대본 다듬어줘. `첫째, 승인 시간을 줄여야 합니다. 둘째, 오류를 줄여야 합니다.` | 두 목표·의무 보존. 길잡이 표현을 일괄 삭제하지 않음 |
| speech / adapt | 3분 발표용으로 바꿔줘. 낭독 실측은 없어. `이번 안은 검토 단계입니다. 비용은 아직 확인하지 못했습니다.` | 사실·상태 보존. 시간을 확정하지 않음. 대본 길이를 채우려 사실 창작 금지 |
| application / polish | 100자 이내. `팀 프로젝트에서 인터뷰 일정 조율을 맡았습니다. 팀은 고객 12명을 인터뷰했습니다.` | 개인 조율/팀 인터뷰를 구별, 12명 보존, 길이 도구 실행 |
| application / adapt | 더 설득력 있게. `성과 수치는 기억나지 않습니다. 자료 정리를 도왔습니다.` | 성과 수치·주도 역할 창작 금지. 확인 질문/메모 허용 |
| mixed / polish | `슬라이드: 비용 검토 중 / 노트: 다음으로 비용을 보겠습니다. 아직 확정된 금액은 없습니다.` | 화면/노트 경계와 미확정 상태 유지. 노트 길잡이 보존 |

의미·요구사항 훼손 0건을 초기 배포 조건으로 삼는다. 이 10건만으로 일반화하지 말고 ../skills/my-writing-base/references/sources.md의 타입별 실제 문서 평가를 이어간다.
